# ADR-0023: 운영 API를 단일 컨테이너로 교체한다

| 항목 | 값 |
| --- | --- |
| 상태 | Accepted |
| 날짜 | 2026-09-09 |
| 관련 | #565 |

## 맥락 (Context)

운영 서버는 Amazon Linux 2023 ARM64와 t4g.medium으로 시작한다. 사용자는 블루그린 도입을 미루고 단일 컨테이너 배포를 요청했다. API는 메모리 WebSocket 브로커와 단일 인스턴스 전제의 스케줄러를 사용한다.

## 결정 (Decision)

GitHub Actions를 수동 실행해 선택한 ref의 SHA로 ARM64 이미지를 빌드한다. production Environment의 배포 허용 브랜치 정책으로 실행 범위를 제한한다. 테스트와 admin 빌드를 통과한 뒤 서버의 버전별 디렉터리에 배포한다. API 교체 중 중단과 WebSocket 재접속을 허용한다. Redis·AI는 유지하며 기동 상태만 보장한다. DB는 validate로 검증하고 스키마 변경은 사전 운영 절차로 분리한다. 실패 시 작업을 실패로 종료하고 이전 릴리스로 수동 복원한다.

운영 모니터링은 같은 EC2에서 기존 Prometheus·Grafana·Loki 및 수집기를 기동하고 데이터 볼륨을 유지한다. 관리 포트는 loopback에 제한한다. 배포 전에 Java 릴리스 소스 전체를 검사하고 배포 성공 판정에 모니터링 준비 상태 확인을 포함한다.

## 고려한 대안 (Considered Options)

1. 단일 API 교체: 작은 운영 구성으로 시작할 수 있으나 배포 중 중단된다.
2. 같은 EC2의 컨테이너 블루그린: 새 버전을 먼저 확인할 수 있으나 스케줄러 중복 실행, WebSocket 분리와 추가 메모리를 다뤄야 한다. 필요해질 때 별도 도입한다.

## 결과 (Consequences)

### 긍정

동시에 두 API를 실행하지 않고 기존 데이터 볼륨을 유지한다. SHA별 이미지와 릴리스 파일로 복원 대상을 식별한다.

### 부정 / 트레이드오프

API와 Nginx 교체 시 중단된다. 진행 중 비동기 영상 처리는 별도 완료 확인이 필요하다. DB 변경은 이미지 복원으로 되돌릴 수 없다. 단일 EC2 장애에 대한 고가용성을 제공하지 않는다.

## 후속 / 미결정

도메인·서버 주소·운영 자격증명은 배포 환경에 입력한다. CPU 크레딧, 메모리 및 영상 처리 부하는 실제 ARM 서버에서 측정한다. LLD: N/A — API·도메인 모델 변경 없이 배포 설정과 절차를 추가하며 인수조건은 운영 문서에서 관리한다. 릴리스 전체 정적 검사를 통과시키기 위한 Java 변경은 기존 분기와 DTO 생성 경로를 동등한 `if` 분기·팩터리 호출로 옮긴 동작 보존 리팩터링이며, API·스키마 계약을 변경하지 않는다.
