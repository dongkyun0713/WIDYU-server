# ADR-0032: 측정회차 내보내기 — 원문 재조립과 워커

> Architecture Decision Record. 하나의 중요한 의사결정과 그 이유를 기록한다.

| 항목 | 값 |
| --- | --- |
| 상태 | Accepted |
| 날짜 | 2026-09-20 |
| 관련 | LLD-0050, #654, ADR-0030 v2, ADR-0031, 내보내기 형식서 `EXPORT_FORMAT.md`(v0.2) |

## 맥락 (Context)

작업지시서 B9는 한 측정회차를 `run_<run_id>.zip` 하나로 꺼내라고 한다. 형식은 「서버 내보내기 형식서」가 정본이고 계약검사기 `check_export.py`가 그 형식을 읽는다. 완료 기준은 검사기 FAIL 0건이다. 연구 자료 보전 경로가 여기 걸려 있다(질의 ④, L5).

서버의 저장 레이아웃은 내보내기 레이아웃과 다르다. IMU·심박은 배치 1건 = S3 객체 1개 + `sensor_batch` 인덱스 행이고(ADR-0030 v2·0031), 위치·하트비트는 RDB 행에 원문 텍스트가 있다(LLD-0048·0049). 내보내기는 이를 **회차·스트림·기기 단위 JSONL**로 재조립하고, 레코드마다 서버 봉투 `_server{}`를 붙이며, `manifest.json`·`run.json`·`clock_mappings.json`·`quality.json`을 재계산해 만든다. 회차가 크면(3시간 × 워치 3대 ≈ 56만 샘플) 즉시 응답이 어렵다.

결정할 것은 셋이다. 원문에 봉투를 어떻게 붙이는가, 잡을 어떻게 돌리는가, 보존 정보가 없는 회차를 어떻게 내보내는가.

## 결정 (Decision)

1. **봉투는 원문 JSON 객체를 파싱해 키를 넣고 다시 직렬화한다.** 원문 문자열 끝에 텍스트를 끼워 넣지 않는다. 앱 원문 필드는 최상위 그대로 두고, 서버가 붙이는 것은 `member_id`·`stream`(없을 때)·`batch_id`(위치·하트비트처럼 앱이 안 붙이는 스트림은 서버 행 ID로)·`boot_id`·`clock_mapping_id`(clock 블록이 있는 스트림)·`_server{}`뿐이다. 재직렬화로 표기(공백·숫자 표기)는 바뀔 수 있지만 값은 보존되고 나노초 문자열은 문자열로 남는다. **원문 바이트의 정본은 S3 객체·RDB `payload` 컬럼이고 `payload_sha256`은 그 원문 기준이다**(형식서 I9가 NOT_IMPLEMENTED인 이유와 같다).
2. **잡은 `@Async`가 아니라 아웃박스 폴링 워커다.** `run_export` 행을 `QUEUED`로 만들고 `@Scheduled` 워커가 하나씩 집어 `RUNNING → DONE/FAILED`로 옮긴다. 프로세스가 재시작돼도 큐가 남고, 상태 갱신은 `REQUIRES_NEW`로 짧게, 자료 읽기는 스트림 단위 `readOnly`로 나눠 긴 트랜잭션을 만들지 않는다. `FcmOutboxDispatcher`가 같은 패턴이다.
3. **보존 정보가 없는 회차도 내보낸다.** `run.json`의 `retention{}`은 형식서가 필수로 못 박았지만 값 집합은 미정이다. 회차에 `data_policy`가 없으면 `{"data_policy": "UNDECIDED", 날짜 셋: null}`로 싣는다. 「없으면 수집 거부」 게이트는 실증 기간 완화됐고(질의 ①), 보존 결정이 빠진 상태를 **숨기지 않고 값으로 적는 것**이 정책서 1.2.3(관측 못 했으면 null, 채우지 않는다)의 정신에 맞다.
4. **`expected_sample_count`는 기기 배정 구간 × 설정 표본율이다**(X7, 사용자 결정 2026-09-20). 미착용·계획 중단 구간을 분모에서 빼지 않는다. 자료와 함께 줄이면 수집률이 스스로를 변호한다.
5. **결측 구간은 배치 경계 갭에서 계산한다.** 스트림별 갭 문턱(설정값)을 넘는 공백을 `missing_intervals`로 적고, 사유는 그 구간의 하트비트로 설명되면 그 값(`NOT_WORN`·`DEVICE_OFF`), 아니면 `UNKNOWN`이다. 빈칸으로 두지 않는다. `disposition`은 `UNRECOVERED`다(레코드가 있으면 갭이 아니므로 복구 구간은 원리적으로 생기지 않는다).
6. **다운로드는 S3 presigned GET(15분)이다.** zip은 `exports/{runId}/{exportId}/run_{runId}.zip`에 두고 서버는 URL만 준다.

## 고려한 대안 (Considered Options)

1. **원문 문자열 끝에 `,"_server":{…}`를 텍스트로 삽입** — 바이트 보존에 가깝지만 원문이 `}`로 끝나지 않거나 공백·주석이 있으면 깨지고, 중복 키(앱이 `member_id`를 보냈을 때)를 막을 수 없다. 원문 정본은 어차피 S3·DB에 있으므로 기각.
2. **`@Async` 잡** — 재시작 시 큐가 사라지고 `@Transactional` 규칙(훅 규칙 6)과 긴 트랜잭션이 충돌한다. 기각.
3. **동기 응답으로 zip 스트리밍** — 회차가 크면 타임아웃. 기각.
4. **보존 정보 없는 회차 거부** — 실증 기간에 내보내기 자체가 막혀 자료 보전 경로가 끊긴다. 기각.
5. **스트림 파일 분할(X5)** — 실측 전. 회차·기기당 1파일로 시작한다.

## 결과 (Consequences)

### 긍정
- 형식서 §1~§7을 서버 저장 구조 변경 없이 만족한다. 저장은 원문 그대로, 재조립은 내보내기에서만.
- 검사기가 재계산하는 값(줄 수·샘플 수·시각 범위·파일 해시·수집률)을 서버도 파일에서 다시 세어 적으므로 I1·I6·I7이 자기 검증이 된다.
- 워커 패턴이라 실패한 내보내기는 `FAILED`로 남고 다시 요청할 수 있다.

### 부정 / 트레이드오프
- 스트림 파일의 줄은 원문과 바이트 단위로 같지 않다(재직렬화). C9-1(왕복 일치)은 서버 쪽에서 원문 해시로 확인한다.
- 위치·하트비트 레코드에는 `boot_id`·`clock_mapping_id`가 없다(앱이 clock을 보내지 않는다). 검사기 C1·B2가 그 스트림에서 NOT_MEASURABLE을 낼 수 있다. 사유 목록에 적는다.
- 인시던트·판정 기록(B10)·측정(P1)은 아직 없어 `streams_absent`/파일 부재로 신고한다. K1·L2 등은 NOT_MEASURABLE이다.
- `missing_reason`·`disposition`·`streams_absent[].reason`·시계 도메인·`transform`·`evidence_method` 값 집합(X1·X8·X9)은 미정이라 상수로 두고 설정값으로 뺀다. 확정되면 값만 바꾼다.
- 워커가 한 번에 하나씩 처리한다. 동시 요청은 큐에서 기다린다.

## 후속 / 미결정
- 검사기 D2는 보강 레코드를 원 배치에 병합하지 않는다. 충격 뒤 10초 구간의 acc 배치는 자기 안에 gyro를 실어야 결측으로 잡히지 않는다(앱 계약 확인 항목).
- 판정 기록(`decisions.jsonl`)은 B10 뒤 이 잡에 붙인다.
- 수용 영수증(K3)·ECG 오프셋(K4)은 `run.json` 자리만 둔다.
- 파일 분할(X5), 내보내기 보존 기간·삭제, presigned 유효 시간 조정은 운영 뒤.
- `wear_state`(S1 자리 미정)는 `missing_intervals`에 싣지 않는다.
