# ADR-0017: 심박 전송을 배치에서 단건으로 전환

> Architecture Decision Record. 하나의 중요한 의사결정과 그 이유를 기록한다.

| 항목 | 값 |
| --- | --- |
| 상태 | Accepted |
| 날짜 | 2026-08-18 |
| 관련 | ADR-0013(대체), LLD-0019, LLD-0023 |

## 맥락 (Context)

ADR-0013은 AI 계약이 15개 배열에서 단건 JSON(`POST /api/hr`)으로 바뀐 뒤에도
앱의 15개 WebSocket 배치 계약을 유지하고, 백엔드가 배치를 순차 단건 호출로 변환하도록 결정했다.
당시 대안 1(앱이 한 건씩 전송)은 "WebSocket 호출 빈도와 앱 계약 변경이 커진다"는 이유로 기각되었다.

그 뒤 운영에서 배치 유지 비용이 드러났다.

- 심박 이상치 조회 API를 초 단위로 폴링해도 최신값이 갱신되지 않는다는 보고가 있었다.
- dev 로그 실측 결과 워치는 1초 간격 측정값 15개를 약 15.5초마다 전송한다.
  서버의 최신 심박은 배치가 저장되는 시점에만 바뀌므로, 조회 주기와 무관하게 15초 동안 같은 값이 반환된다.
- 당초 지연 원인으로 의심했던 AI 순차 호출은 배치당 14~81ms로 기여가 미미했다.
  지연은 전적으로 배치 수집 주기에서 발생한다.

AI는 이미 단건 계약이므로 배치는 AI 요구사항이 아니라 앱 계약을 보존하기 위한 선택이었다.
`context` 전송 여부 확인 등으로 앱 변경이 이미 필요한 상황이 되면서 그 전제가 약해졌다.

## 결정 (Decision)

앱이 측정값을 **1초마다 1건씩** 전송하는 경로를 도입하고, 서버는 수신 즉시 AI에 단건 전달 후 저장한다.

기존 15개 배치 경로(`/app/heart-rate/send`)는 **당분간 함께 유지**한다.
워치 앱이 전환을 마친 뒤 별도 작업으로 제거한다.

멱등성 기준은 배치 시작 시각에서 측정 시각 단건으로 바뀐다.
`heart_rate_event`의 `(member_id, measured_at)` 유니크 제약을 그대로 사용한다.

### 2026-09-08 후속 결정 (#556)

워치 앱의 단건 전송 전환을 마무리하고 기존 배치 경로와 배치 전용 요청·처리·저장 코드를 제거한다.
서버의 심박 전송 계약은 `/app/heart-rate/send-single` 하나로 단일화한다.

결과 ACK는 Spring user destination이 사용하는 인증 Principal 이름(`memberId`)을 사용자 키로 사용하고,
STOMP session header로 현재 발신 세션을 지정한다. 같은 회원의 다른 세션에는 ACK를 전달하지 않는다.

## 고려한 대안 (Considered Options)

1. **배치 유지** — 변경이 없지만 초 단위 조회 요구를 충족할 수 없다.
2. **배치 크기 축소(15 → 3~5개)** — 지연을 3~5초로 줄이면서 앱 변경이 작다.
   다만 지연이 남고, AI가 단건 계약인데 배치를 유지하는 구조적 부자연스러움도 남는다.
3. **단건 전송으로 전환** — 지연이 사라지고 서버 구현이 단순해진다.
   메시지·트랜잭션 빈도가 15배로 늘어난다.

## 결과 (Consequences)

### 긍정

- 최신 심박 조회 지연이 배치 수집 주기만큼(약 15초) 사라진다.
- AI 단건 계약과 전송 계약이 일치해, 배치 정렬·최신값 추출·배치 멱등성 로직이 불필요해진다.
- AI 호출 총량은 변하지 않는다. 배치당 15회를 15개 요청에 1회씩으로 나눌 뿐이다.
- 측정값 하나가 유효하지 않아도 나머지 측정이 영향을 받지 않는다.
  배치에서는 값 하나가 잘못되면 15개 전체가 저장되지 않았다.

### 부정 / 트레이드오프

- 시니어 1명당 WebSocket 메시지가 약 0.065건/초에서 1건/초로 늘어난다.
  DB 저장 트랜잭션도 같은 비율로 늘고 각각은 더 짧아진다.
- 동시 접속 시니어 수에 비례해 부하가 선형 증가한다. 규모가 커지면 측정이 필요하다.
- 전환 기간에는 두 경로가 공존했으나 #556에서 배치 경로를 제거했다.
- AI의 위급 판정은 30초 지속을 시간 기준으로 보므로 전송 단위와 무관하다.
  단건 전환으로 판정 결과가 달라지지 않는다.

## 후속 / 미결정

- 배포 전 워치 앱에서 배치 경로 사용이 종료됐는지 확인한다.
- 동시 접속 규모가 커질 때 메시지 유입량과 DB 쓰기 부하를 측정한다.
  필요하면 저장을 묶어 쓰는 방안을 별도로 검토한다.
