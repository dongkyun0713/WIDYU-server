# ADR-0029: 결제는 포인트를 충전·환수하지 않는다

> Architecture Decision Record. 하나의 중요한 의사결정과 그 이유를 기록한다.

| 항목 | 값 |
| --- | --- |
| 상태 | Accepted |
| 날짜 | 2026-09-17 |
| 관련 | LLD-0039, LLD-0003, ADR-0012, #624 |

## 맥락 (Context)

포인트는 활동 보상 전용으로 확정했다. 시니어 가입 100p, 복약 인증·걷기 목표·건강 일정 방문 적립, 앨범 잠금해제 50p 차감만 잔액을 바꾼다. Toss 결제는 향후 응급 알람 월 구독 상품으로 전환할 예정이며, 구독 상품과 0원 결제 구현은 보류 상태다.

그동안 결제 흐름은 승인 시 패키지 포인트를 적립하고, 취소 선점 시 환수 포인트를 즉시 차감해 예약했으며, 취소 포기·중단 시 예약을 반환했다(ADR-0012). 이 결합이 남아 있으면 구독 전환 뒤에도 결제 코드가 포인트 잔액을 건드린다.

## 결정 (Decision)

- 결제 승인은 포인트를 적립하지 않는다. `PaymentTransactionService`는 `SeniorProfileService`를 의존하지 않는다.
- 결제 취소는 포인트를 차감·예약·반환하지 않는다. ADR-0012의 "환수 포인트를 취소 선점 시 즉시 차감해 예약한다" 결정은 이 문서가 대체한다. 멱등 키·행 잠금 직렬화 결정은 그대로 유효하다.
- `PointChargePackage`는 `pointAmount`를 갖지 않는다. `payment_order.point_amount`, `payment.canceled_point_amount`, `payment_cancel.cancel_point_amount` 컬럼과 응답 필드는 호환을 위해 유지하고 항상 0을 기록한다. 컬럼 삭제는 클라이언트가 해당 필드를 읽지 않게 된 뒤 후속 작업으로 진행한다(LLD-0039 §8).
- 이 결정 이전에 포인트를 충전한 결제를 배포 후 취소하면 PG 환불만 수행하고 포인트는 환수하지 않는다.
- Toss 승인·취소·복구 스케줄러·Feign·멱등 처리 코드(ADR-0016, LLD-0016·0017·0022)는 바꾸지 않는다.

## 고려한 대안 (Considered Options)

1. **포인트 결합만 제거, 컬럼·필드 유지 (채택)** — DDL 없이 배포하고 클라이언트 응답 계약을 유지한다 / 항상 0인 필드가 남는다.
2. **포인트 컬럼·필드까지 즉시 삭제** — 죽은 필드가 없다 / NOT NULL 컬럼이라 배포와 DDL을 강결합해야 하고 응답 계약이 바뀐다.
3. **레거시 결제의 환수 로직만 유지** — 과거 충전분 취소 시 포인트가 회수된다 / 결합 제거 목적과 충돌하고 예약·반환 코드가 그대로 남는다.

## 결과 (Consequences)

### 긍정
- 결제 승인·취소 어느 경로도 `SeniorProfile.points`·`PointHistory`를 바꾸지 않는다.
- 구독 상품 전환 시 결제 코드에서 포인트 관련 분기를 고려하지 않아도 된다.

### 부정 / 트레이드오프
- 배포 시점에 `payment_cancel.status='PENDING' AND cancel_point_amount>0`인 행이 있으면 이후 중단 경로에서 예약 포인트가 반환되지 않는다. 배포 전 0건을 확인하고, 있으면 수동 반환한다.
- LLD-0015·0017·0022·0035와 PR 기록의 포인트 서술은 역사적 기록이다. 현재 동작은 LLD-0039를 따른다.

## 후속 / 미결정

- 포인트 컬럼 삭제 DDL 실행 시점 (LLD-0039 §8).
- 응급 알람 구독 상품과 0원 결제 설계는 별도 ADR·LLD로 다룬다.
