# ADR-0025: 일본 현장실증 환경을 프로파일로 격리하고 허용 기능만 노출한다

| 항목 | 값 |
| --- | --- |
| 상태 | Accepted |
| 날짜 | 2026-09-11 |
| 관련 | #572, apiDocs/japan/japan-pilot-implementation-plan.md (1단계) |

## 맥락 (Context)

일본 현장실증은 참여자의 심박·위치를 수집한다. 제출한 개인정보·안전 요구사항을 지키려면 실증 환경을 운영과 격리하고, 실증에 필요한 기능만 노출해야 한다. 기존 서비스는 단일 보안 필터 체인과 다수의 자동 알림 스케줄러·리스너를 항상 활성화하므로, 실증에서 불필요한 가입·업로드·결제·자동 알림이 그대로 동작한다.

회차 상태·동의·실제 측정 DTO·삭제 계약은 후속 단계(2단계 이후)에서 LLD로 확정한다. 본 ADR은 여러 도메인에 걸치는 **격리·접근 정책**만 다룬다.

## 결정 (Decision)

1. **전용 `pilot` 스프링 프로파일**을 도입한다. 실증 배포는 이 프로파일로만 기동하고, 운영 프로파일(`local`/`dev`/`prod`/`test`)과 동시 활성화되면 기동을 실패시킨다.
2. **격리 확인 게이트**를 둔다. `pilot.isolation-confirmed=true`와 `pilot.firebase-project-id`가 명시되지 않으면 기동하지 않는다. 배포자가 격리된 자원을 사용한다고 의도적으로 선언해야 실증이 시작된다.
3. **보안 필터 체인을 프로파일별로 분리**한다. `pilot` 체인은 실증에 필요한 경로(심박·실시간 위치·부모 위치·홈·FCM 토큰 등록·WS 일회용 토큰 발급)만 인증 후 허용하고, 그 외 모든 HTTP 요청은 `denyAll`로 차단한다(가입·소셜·SMS·가족 초대·앨범/업로드·결제·외부 검색 포함). Actuator는 health만, Swagger는 전부 차단한다. 가상 복약 조회는 외부 검색(`/search`)·사진 업로드(`/verify`)와 경로가 섞여 있어, 정확한 조회 경로를 앱팀과 확정한 뒤 5단계에서 추가한다.
4. **STOMP SEND/SUBSCRIBE에도 허용 목록**을 적용한다. SEND는 알려진 목적지와 정확히 일치할 때만, SUBSCRIBE는 숫자 대상 ID(`/topic/heart-rate/{id}`·`/topic/location/senior/{id}`) 또는 개인 큐와 정확히 일치할 때만 통과시킨다. 브로커의 와일드카드 구독(`/topic/heart-rate/*`)으로 다른 가족 브로드캐스트를 수신하지 못하도록 접두사 매칭을 쓰지 않는다.
5. **불필요한 백그라운드 작업을 실증에서 제외**한다. 스케줄러는 `@EnableScheduling` 지점에서 일괄 제외하고, 위치 이벤트로 발동하는 안전구역·건강일정 알림 리스너와 복약·걷기·건강일정·앨범 자동 알림 리스너를 `@Profile("!pilot")`로 제외한다.

## 고려한 대안 (Considered Options)

1. **운영 환경에 테스트 계정만 추가** — 운영 데이터·알림·백업 분리 요구를 충족하지 못해 제외한다.
2. **범용 기능 플래그 시스템 도입** — 실증 1건에 과한 복잡도라 제외한다. 프로파일과 `@Profile` 게이팅으로 충분하다.
3. **분리 환경 + `pilot` 프로파일 (채택)** — 기존 JWT·가족 검증·DB/Redis 구성을 재사용하면서 실증 정책을 공통 제어 지점에 적용한다.

## 결과 (Consequences)

- 실증은 운영과 별개 프로파일·자원으로만 기동하며, 격리 선언 없이는 부팅되지 않는다.
- 허용하지 않은 HTTP/STOMP 요청과 불필요한 외부 알림이 실증에서 차단된다.
- 실증용 계정 접근 경로(회차·지정 계정)는 2단계에서 추가한다. 현재 `pilot` 체인은 로그인 계열 경로도 차단하므로, 1단계 검증용 토큰은 별도로 발급해 사용한다.
- 허용 경로·STOMP 목적지 목록은 앱팀 확정 전 계획서 기준 초안이며, 확정 시 목록을 좁힌다(미결정 사항).
- 운영 데이터·자원의 물리적 분리(DB·Redis·Firebase·JWT 키·관리자 계정)는 인프라·백엔드 합동 작업으로 별도 진행한다. 본 ADR은 애플리케이션 계층 격리만 보장한다.
