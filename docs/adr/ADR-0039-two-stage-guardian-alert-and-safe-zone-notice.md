## 맥락 (Context)

2026-10-05 추가본은 서버 PR 묶음(#695~#733)을 항목별로 대조해 대부분을 「PR 대로」 받아들이면서 안전 알림의 뼈대를 바꿨다. ADR-0038은 「60초 본인확인 → 활성 보호자 전원에게 `INITIAL_ALERT` → 5분 자동전화·`FINAL_ESCALATION`」을 전제했고, 안심구역 이탈도 같은 사건 흐름에 넣었다. 새 정책은 ① 보호자 1차 알림을 **현재 방장 한 명**에게만 보내고, ② 3분 안에 보호자 멈춤 기록이 없으면 **안전 알림을 켠 보호자 전원**에게 2차 알림을 1회 보낸 뒤 **더 보내지 않는다.** 자동전화·반복 푸시·119는 만들지 않는다. 안심구역 이탈은 위험 경보가 아니라 외출·돌아옴 소식이므로 시니어 확인·사건·60초 지연 없이 보통 우선순위로 보낸다. 시니어가 워치에서 직접 도움을 요청하는 새 사건 종류가 생기고, 보호자 앱이 끝난 상황을 구분해야 하므로 상황 상태 조회가 필요하다. 「함께 정할 것」(B2·B3·B4·B6·B7·B11·B12·B13 등)은 정해지지 않았다. 이 ADR은 추천안을 **가정**으로 적어 구현하고, 회신이 오면 가정을 바꾼다.

## 결정 (Decision)

1. **보호자 알림은 두 단계로 끝난다.** ① `INITIAL_ALERT`는 현재 가족 **방장 1명**에게만 보낸다(플래그 OFF 즉시 발송 경로·HELP 경로도 동일). 방장이 없으면 예외 없이 WARN을 남기고 ① 게이트(`initial_alert_sent_at_ms`)와 ② 마감 시각을 그대로 기록한다. 따라서 3분 뒤 멈춤 기록이 없으면 방장 유무와 관계없이 ②가 나간다(LLD-0081). ② `SECOND_ALERT`(단계명 제안)는 ① 기준 시각 + 3분(`second_alert_due_at_ms`)에 멈춤 기록이 없을 때 1회, 대상은 그 시니어의 `SAFETY` 설정 그룹 수신 대상 가운데 안전 알림 푸시가 켜진 보호자 전원(방장 포함, 방장은 두 번째 푸시)이다. 푸시가 꺼진 수신 대상은 센터 행만 남는다. 방장의 센터 행은 ①의 행을 재사용한다(수신자×이벤트 1행, `eventId = incident_ref`). ② 뒤에는 아무것도 보내지 않는다. ADR-0038 결정 8의 자동전화·`FINAL_ESCALATION`, 카탈로그 S06·S07 미대응 재알림은 폐기한다.
2. **② 발송은 ① 게이트와 같은 방식이다.** 사건에 ② 마감 시각을 저장하고 같은 스케줄러가 조건부 UPDATE(`second_alert_sent_at_ms IS NULL AND 멈춤 없음 AND due <= now`)로 claim한 트랜잭션만 enqueue한다. 직전에 사건 활성 여부·멈춤·현재 방장·수신 대상·푸시 설정을 다시 읽는다. 서버 재시작에도 이어진다. 가정(B2): ① 기준 시각은 enqueue 시각(`initial_alert_sent_at_ms`)이며, 전송이 계속 실패하면 `DELIVERY_FAILED`만 표시하고 3분은 그대로 센다. 가정(B3): 멈춤과 ②가 겹치면 조건부 UPDATE 하나로 먼저 커밋된 쪽만 인정한다.
3. **멈춤 기록은 「사건 × 보호자 × 종류」당 1건이다.** 종류는 `ACKNOWLEDGED`(덮는 모달 `확인`)·`MESSAGE_SENT`·`CALL_INITIATED`. 기록이 하나라도 생기면 미발송 ②를 취소한다. 푸시 도착·탭·앱 열기·열람·읽음·메시지 작성 화면만 연 것은 멈춤이 아니다. 한 보호자의 멈춤을 다른 보호자에게 알리거나 표시하지 않는다. 가정(B4): 기존 `POST /api/v1/incidents/{id}/guardian-response`를 확장한다(별도 `/safety-events/{id}/acknowledgements`는 만들지 않음).
4. **FCM data에 단계와 상황 ID를 싣는다.** `deliveryStage`(`INITIAL_ALERT`/`SECOND_ALERT`)·`safetyEventId`(= `incident_ref`). `HEART_RATE_EMERGENCY`의 `foregroundPresentation`은 `MODAL`로 바꾼다(앱 사용 중 덮는 모달 S11). 긴급 푸시 형식(`widyu_safety`·high·`time-sensitive`)은 ADR-0037 D8 그대로. 가정: 시간 민감은 M04만 유지하고 M02·M03·H01은 보통으로 내린다.
5. **안심구역은 사건이 아니다.** 이탈은 `openForAlert(SAFE_ZONE_EXIT)`로 열지 않는다(LLD-0071의 사건화, S02/S05/S07, S09 OK 안내, 안심구역 후속 질문 카드 `SAFE_ZONE_V1`을 되돌린다). 나감 `SAFE_ZONE_EXITED`는 `INTERACTION` 우선순위·`BANNER`·Z01 제목만, 돌아옴은 새 타입 `SAFE_ZONE_ENTERED`·Z02 「…안심구역으로 돌아왔어요.」로 보낸다. 기존 재진입 판정을 쓰고 Redis `safezone:alert:{memberId}` 30분 묶기를 복원한다. 수신자·설정(`SAFE_ZONE` 그룹, 방장 강제, 센터 `LOCATION`, 보존 90일)은 ADR-0037 그대로. 시니어에게는 아무것도 보내지 않는다. 가정(B6): 한 30분 창에서 나감 알림과 첫 돌아옴 알림은 각각 최대 1회다. 돌아옴은 Redis 키를 지우지 않고 `EXITED→RETURNED`로 바꾸며 TTL은 유지하므로, 창 안의 재이탈·재진입은 알리지 않고 TTL 만료 뒤 다음 이탈부터 새 창을 연다(LLD-0078). ADR-0038 결정 6의 「안심구역 재진입 = 상황 종료」는 사건이 없어지므로 의미를 잃는다.
6. **시니어 응답 시도 이력을 남긴다.** 반영되지 않은 응답(두 번째 기기·마감 뒤)도 응답값·`response_via`·단말 시각·서버 시각·수락/지각/중복을 별도 테이블에 적는다. 조건부 UPDATE로 첫 응답 하나만 상태에 반영하는 규칙(ADR-0038 결정 4)은 유지한다. 가정(B7): 워치 `취소`는 폰이 대리 전송하든 워치가 직접 보내든 같은 API로 들어오며 `response_via=WATCH`.
7. **상황 상태 조회를 제공한다.** 가정(B11): `GET /api/v1/incidents/{incidentRef}/status`가 `status=OPEN|ENDED`·`endedAt`를 돌려주며, 「끝남」은 시니어 취소·마지막 감지 뒤 5분 경과·RESOLVED를 계산해 판정한다(5분 종료는 스케줄러가 찍지 않으므로 조회 시 계산). 끝난 뒤 들어온 `ACKNOWLEDGED`는 저장만 하고 ②에 영향이 없다.
8. **워치 도움 요청은 새 사건 종류다.** `IncidentKind.SELF_HELP_REQUEST`(이름 제안), `POST /api/v1/incidents/help-requests`, `POST /api/v1/incidents/{incidentId}/cancel`(경로 제안). 60초 확인 없이 ① 방장 → 3분 → ②를 결정 1·2와 공유한다. 취소는 사건을 `CANCELLED_BY_SENIOR`(상태 제안)로 끝내고 미발송 ②를 보내지 않으며 ①을 받은 보호자에게 일반 우선순위 취소 안내를 보낸다. 같은 워치의 연속 요청은 열린 요청 사건에 붙는다. 가정: 심박 사건이 열린 중의 도움 요청은 그 사건에 HELP로 붙이고, 취소 안내는 센터 `위치`에 저장하며, ② 뒤 취소면 ② 수신자에게도 안내한다. 문구에 「응급 감지」를 쓰지 않는다.
9. **낙상·복약·건강일정은 범위 밖이거나 조건부다.** 낙상은 지금 서버 동작을 바꾸지 않는다. 정각 복약 서버 푸시 제거는 앱 기기 알람 배포와 함께 하므로 설정 스위치(`sensor.medication.on-time-push`, 기본 true)로 남긴다(B12 추천). 건강일정은 방문 인증 완료 일정의 수정·삭제를 서버가 거부한다.
10. **본인확인 60초는 확인 화면이 뜬 때부터 센다(2026-10-13 추가).** 시니어 앱이 확인 화면을 띄우는 즉시 수신 완료를 보내고, 서버는 그 시각 + 60초를 응답 마감으로 삼는다. 푸시 뒤 90초 안에 수신 완료가 없으면 화면을 받지 못한 것으로 보고 무응답 처리해 ①을 보낸다. 이유: 「휴대폰이 꺼져 화면을 못 봤다」와 「화면을 보고도 누르지 못했다」를 구분하고, 푸시가 늦게 도착해도 시니어에게 60초를 보장한다. 신호가 없으면 결국 ①이 나가므로 휴대폰이 꺼진 경우에도 보호자 알림이 사라지지 않는다. 대가: 휴대폰이 꺼진 경우 ①이 90초로 늦어지고, 최대 대기는 150초다. 수신 완료를 타이머 시작 조건으로만 쓰는 안(수신이 없으면 타이머가 시작되지 않음)은 휴대폰이 꺼졌을 때 ①이 영영 나가지 않아 기각했다. 낙상은 결정 9대로 60초를 유지한다. → LLD-0085

## 고려한 대안 (Considered Options)

- **② 대신 자동전화 유지(ADR-0038 결정 8)** — 정책이 폐기했다(RECONCILIATION v0.2 T3 보류). 기각.
- **② 발송을 별도 지연 큐(Redis/스케줄러 잡)로** — ① 게이트와 두 가지 방식이 공존해 재시작·중복 처리 규칙이 둘이 된다. 같은 스케줄러의 조건부 UPDATE로 통일. 기각.
- **멈춤 기록을 사건 행의 컬럼(첫 1건)으로 유지** — 「누가·언제·무엇」을 보호자별로 남기라는 요구와 맞지 않는다. 테이블 분리.
- **안심구역을 사건으로 두고 60초만 생략** — 정책이 「사건 아님」을 명시했고, 사건을 두면 묶기·종료·후속 카드가 따라온다. 기각.
- **`ACKNOWLEDGED`용 새 API(`/safety-events/{id}/acknowledgements`)** — UX v0.4의 제안이지만 추가본 A6은 기존 반응 기록 API를 넓히라고 한다. 기존 API 확장(가정, B4).
- **상태를 목록 API 항목에 포함** — 목록 응답이 사건 상태를 매번 계산해야 하고 다른 타입 항목에는 의미가 없다. 별도 조회 API(가정, B11).

## 결과 (Consequences)

### 긍정
- 보호자 알림이 최대 2회로 예측 가능해지고, 방장 한 명이 먼저 대응할 여지가 생긴다.
- 안심구역이 사건 흐름에서 빠져 `incident`·후속 카드·OK 안내가 심박 하나로 단순해진다.
- 멈춤·응답 이력이 보호자별·시도별로 남아 사후 분석과 S12 분기가 가능하다.

### 부정 / 트레이드오프
- 방장이 알림을 못 받거나 방장 미지정이면 3분 동안 다른 보호자는 모른다(② 뒤에만 전원). 방장 0명 처리는 WARN+게이트 기록으로 조용히 넘어간다.
- 사건 테이블에 ② 컬럼이 늘고 멈춤·응답 이력 테이블 2개가 추가된다(운영 DDL 선적용).
- LLD-0071(안심구역 사건)과 LLD-0072의 S09 부분을 되돌리므로 머지 직후 한동안 develop에 두 흐름이 공존한다(배포는 2차 웨이브까지 머지한 뒤).
- 「함께 정할 것」 가정(B2·B3·B4·B6·B7·B11)이 바뀌면 해당 LLD의 작은 재작업이 생긴다.
