# LLD-0058: 위치 갱신 롤백 시 안전구역 이탈 알림 복구

## 1. 목적 / 배경

위치 갱신 트랜잭션이 롤백되면 안전구역 이탈 알림이 누락되고 다시 보내지지 않는다.
이탈 처리는 Redis 알림 플래그(`safezone:alert:{memberId}`)와 체류 정보(`location:stay:{memberId}`)를 먼저 쓰고, FCM outbox 행은 DB 트랜잭션과 함께 커밋한다(LLD-0011, LLD-0036).
Redis 쓰기는 롤백되지 않으므로, outbox 저장이나 커밋이 실패하면 플래그가 남아 재감지를 막거나 체류 정보가 이미 "밖"이 되어 이탈을 다시 감지하지 못한다.

## 2. 범위

### In scope

- 변경 모듈: widyu-api
- `SafeZoneAlertService`: 플래그를 잡은 트랜잭션이 롤백되면 플래그를 지운다.
- `RealtimeLocationService.calculateStayInfo()`: 새 체류 정보 저장을 트랜잭션 커밋 이후로 미룬다.
- 트랜잭션 동기화가 없는 호출(단위 테스트 등)은 지금처럼 즉시 처리한다.

### Out of scope

- 알림 플래그·체류 정보를 DB로 옮기는 구조 변경
- 커밋 전 동시 위치 갱신 사이의 경쟁(아래 6절 한계)
- 30분 중복 차단 정책, 안전구역 반경, FCM 발송 정책 변경

## 3. 인터페이스 / API

기존 API 계약 변경 없음. WebSocket `/app/location/update` 응답과 `/topic/location/senior/{memberId}` 브로드캐스트는 그대로다.

## 4. 데이터 모델

DB·Redis 스키마 변경 없음. 키 패턴과 TTL(알림 플래그 1800s, 체류 정보 86400s)은 유지한다.

## 5. 처리 흐름

`RealtimeLocationService.updateAndBroadcast()`의 기존 `@Transactional` 경계 안에서:

1. 이전 체류 정보를 읽고, 새 위치의 안전구역을 판정한다.
2. `SafeZoneAlertService.handleSafeZoneTransition()`
   1. 재진입이면 플래그를 즉시 삭제한다(기존과 동일).
   2. 이탈이면 `set-if-absent`로 플래그를 잡는다. 실패하면 이벤트를 발행하지 않는다.
   3. 플래그를 잡았고 트랜잭션 동기화가 활성이면 `afterCompletion(STATUS_ROLLED_BACK)`에서 플래그를 지우도록 등록한다.
   4. `SafeZoneExitEvent`를 발행한다. 리스너가 같은 트랜잭션에서 outbox 행을 저장한다.
3. 새 체류 정보는 트랜잭션 동기화가 활성이면 `afterCommit`에서 저장하고, 아니면 즉시 저장한다.
4. 응답은 새 체류 정보 객체로 만든다(저장 시점과 무관).

결과:

| 상황 | 플래그 | 체류 정보 | 다음 위치 갱신 |
| --- | --- | --- | --- |
| 커밋 성공 | 유지(30분 중복 차단) | 새 값 | 기존과 동일 |
| outbox 저장 실패·커밋 실패로 롤백 | 삭제 | 이전 값 유지 | 이탈을 다시 감지하고 이벤트 발행 |

## 6. 예외 / 에러 처리

- 새 에러 코드 없음. outbox 저장 예외는 기존처럼 호출자에게 전파되어 트랜잭션을 롤백한다.
- `afterCompletion` 안의 예외는 Spring이 로그로 남기고 삼킨다. 롤백 후 플래그 삭제까지 실패하면 다음 위치 갱신이 플래그 때문에 이벤트를 건너뛰고 "밖" 체류 정보를 커밋하므로 그 이탈 알림은 누락된다. Redis가 롤백 직후에도 실패하는 경우로 보고 이번 범위에서 다루지 않는다.
- `afterCommit` 안의 예외는 Spring이 호출자에게 전달한다. 이미 커밋된 위치 갱신을 실패로 돌려보내지 않도록 체류 정보 저장 예외는 콜백 안에서 잡아 경고 로그만 남긴다. 저장이 실패하면 다음 위치 갱신이 이전 체류 정보를 기준으로 다시 판정하며, 이때 알림은 이미 커밋됐고 플래그가 남아 있어 중복 발송되지 않는다.
- 한계: 같은 시니어의 위치 갱신 두 건이 커밋 전에 겹치고 먼저 잡은 쪽이 롤백되면, 뒤의 건은 플래그 때문에 이벤트를 건너뛴 채 "밖" 체류 정보를 커밋할 수 있다. 위치는 약 60초 간격으로 오므로 이번 범위에서 다루지 않는다.

## 7. 인수조건 (Acceptance Criteria)

- [x] 이탈 플래그를 잡은 트랜잭션이 롤백되면 `safezone:alert:{memberId}`를 삭제한다.
- [x] 이탈 플래그를 잡은 트랜잭션이 커밋되면 플래그를 유지한다.
- [x] 이벤트 발행 중 예외가 나도 롤백 시 플래그 삭제가 등록되어 있다.
- [x] 트랜잭션이 롤백되면 체류 정보를 저장하지 않고, 커밋되면 저장한다.
- [x] 트랜잭션 동기화가 없으면 체류 정보를 즉시 저장한다(기존 동작).
- [x] 커밋 후 체류 정보 저장이 실패해도 위치 갱신 요청에 예외를 전달하지 않는다.
- [x] `bash scripts/harness/verify.sh`가 통과한다.

## 8. 영향 범위 / 마이그레이션

- 체류 정보 저장 시점이 모든 위치 이동에서 커밋 이후로 바뀐다. 롤백된 위치 갱신은 체류 정보에 반영되지 않는다.
- 마이그레이션·배포 설정 변경 없음.
