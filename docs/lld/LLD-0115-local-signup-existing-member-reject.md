# LLD-0115: 로컬 보호자 가입은 기존 회원에 로컬 계정을 붙이지 않는다

> Low-Level Design. 이 문서는 해당 기능 구현과 PR 본문의 **오라클(ground truth)** 이다.

| 항목 | 값 |
| --- | --- |
| 상태 | Review |
| Issue | #853 |
| 관련 ADR | ADR-0002 (JWT 인증/인가) |
| 작성자 | Claude |

## 1. 목적 / 배경

로컬 보호자 가입(`LocalLoginService.signupGuardianWithLocal`)은 SMS로 확인한 전화번호와 이름으로 기존 회원을 찾으면, 회원 유형이나 이미 가진 계정을 보지 않고 그 회원에 로컬 계정(이메일, 비밀번호)을 붙였다. 번호와 이름이 같다는 것만으로 기존 회원 본인이라고 볼 수 없다. 보호자가 시니어를 등록할 때 넣은 시니어 번호, 재할당된 번호, Apple 회원 전화번호 보강으로 잘못 들어간 번호(#838)가 있으면 그 번호를 SMS로 받는 사람이 다른 사람의 회원(시니어 포함)에 로그인 수단을 추가하고 그 회원의 토큰을 받는다.

사용자 결정(2026-10-31): 같은 번호의 기존 회원이 있으면 시니어든 소셜 보호자든 가입을 거부한다. 기존 소셜 계정과의 연동은 이 경로에서 제공하지 않는다.

## 2. 범위

### In scope
- 변경 모듈: widyu-api (`LocalLoginService`, `MemberRepository`, `GuardianAuthDocs`), widyu-domain (`ErrorCode`)
- 로컬 가입은 SMS로 확인한 전화번호의 회원이 하나라도 있으면 거부한다. 이름은 비교하지 않는다. 이름이 달라도 같은 번호의 회원을 새로 만들면 전화번호로 회원을 찾는 다른 경로(`findByPhoneNumber`)가 두 건을 만나 실패하기 때문이다.
- 같은 번호의 회원이 없을 때만 새 보호자 회원과 로컬 계정을 만든다.

### Out of scope
- 기존 소셜 회원에 로컬 계정을 연동하는 기능. 별도 기능으로 다룬다.
- `Member.phoneNumber` 유일 제약. 같은 번호로 동시에 들어온 두 가입이 둘 다 존재 확인을 통과할 수 있는 경쟁은 이번에 막지 않는다(LLD-0094와 같은 후속 과제).

## 3. 인터페이스 / API

```http
POST /api/v1/auth/guardians/sign-up/local
```

요청과 성공 응답은 바뀌지 않는다. 같은 번호의 회원이 있으면 아래 오류를 반환한다.

```json
{
  "code": "AUTH_4021",
  "message": "이미 가입된 전화번호입니다.",
  "data": null
}
```

## 4. 데이터 모델

변경 없음. `MemberRepository.existsByPhoneNumber(String)` 조회 메서드를 추가한다.

## 5. 처리 흐름

1. 임시 토큰으로 임시 회원(SMS로 확인한 이름, 전화번호)을 읽는다 (기존 `GuardianAuthService.localGuardianSignup`).
2. 이메일이 이미 로컬 계정에 있으면 `ALREADY_REGISTERED_EMAIL`(기존).
3. 같은 전화번호의 회원이 있으면 `ALREADY_REGISTERED_PHONE_NUMBER`. 회원, 로컬 계정, 토큰을 만들지 않는다. 예외로 끝나므로 임시 회원도 지우지 않아, 클라이언트는 같은 임시 토큰으로 이메일 찾기나 비밀번호 재설정을 이어갈 수 있다.
4. 없으면 새 보호자 회원과 로컬 계정을 저장하고 토큰을 발급한다(기존).

트랜잭션 경계는 기존 `@Transactional` 그대로다.

## 6. 예외 / 에러 처리

| 조건 | 응답 | 상태 |
| --- | --- | --- |
| 같은 번호의 시니어, 소셜 보호자, 로컬 보호자, 정지(INACTIVE) 회원 | 400 `AUTH_4021` (신규 `ALREADY_REGISTERED_PHONE_NUMBER`) | 저장 없음 |
| 이미 등록된 이메일 | 400 `AUTH_4001` (기존) | 저장 없음 |

탈퇴 회원은 탈퇴 시 전화번호를 지우므로(`Member.maskPersonalInfo`) 거부 대상이 아니다.

이전에는 로컬 계정이 이미 있는 회원이 다른 이메일로 다시 가입하면 로컬 계정 저장이 `uk_local_member` 유일 제약에 걸려 공통 처리기의 409 `REQ_4090`(`DUPLICATE_RESOURCE`)이 났다(코드 경로로 확인, 실행 확인은 안 함). 이제 같은 경우 400 `AUTH_4021`이다.

존재 노출: 응답은 이 번호로 가입된 회원이 있다는 사실만 알리고 회원 유형이나 가입 방식은 알리지 않는다. 이 오류는 SMS 인증으로 번호를 확인한 요청자만 받는다. 같은 임시 토큰으로 호출하는 `getUserProfileByTemporaryToken`은 이미 이름, 번호, 소셜 이메일, 제공자 목록을 돌려주고, 마이페이지의 시니어 추가와 번호 변경은 SMS 인증 없이도 "이미 사용 중인 전화번호"를 알린다. 이번 오류는 이 관례보다 더 노출하지 않는다.

## 7. 인수조건 (Acceptance Criteria)

- [x] A1: 시니어 회원과 같은 번호와 이름으로 로컬 가입하면 `AUTH_4021`이고 로컬 계정과 회원 수가 그대로다.
- [x] A2: 소셜 계정을 가진 보호자와 같은 번호(이름은 다름)로 로컬 가입하면 `AUTH_4021`이고 로컬 계정과 회원 수가 그대로다.
- [x] A3: 로컬 계정이 있는 회원의 번호로 다른 이메일로 다시 가입하면 `AUTH_4021`이고 새 이메일의 로컬 계정이 없다.
- [x] A4: 같은 번호의 회원이 없으면 기존처럼 보호자 회원과 로컬 계정을 만들고 토큰을 반환한다.
- [x] Swagger에 400 `AUTH_4001`, `AUTH_4021`이 반영된다.
- [x] `./gradlew :backend:widyu-api:test`가 통과한다.

## 8. 영향 범위 / 마이그레이션

- DB 변경 없음. ENUM 변경 없음.
- 클라이언트: 로컬 가입에서 400 `AUTH_4021`을 받으면 "이미 가입된 번호" 안내와 로그인, 이메일 찾기 진입을 보여줘야 한다. 이전에 소셜 보호자가 같은 번호로 로컬 가입해 로컬 로그인을 추가하던 흐름은 더 이상 되지 않는다.
