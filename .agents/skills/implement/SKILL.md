# implement

Codex가 설계·구현·테스트·자체 검수까지 수행한다. 공통 규칙은 루트 및 작업 영역 AGENTS.md를 따른다.

## 절차

1. 현재 이슈·브랜치·diff와 관련 ADR/LLD/ERD를 확인한다. 다른 작업의 변경을 섞지 않는다.
2. docs/adr/README.md와 docs/lld/README.md의 기준으로 설계 필요 여부를 판단한다. 필요한 설계가 없으면 템플릿으로 직접 작성한다. 작은 변경은 LLD N/A 사유와 완료 조건을 남긴다.
3. LLD의 실제 미결정 정책·API 계약은 사용자에게 확인한다. 빈 체크박스나 '없음'을 미결정으로 취급하지 않는다. 이미 합의된 설계와 일상적 구현 선택은 반복 승인 없이 진행한다.
4. 변경 범위·완료 조건·검증 방법을 짧게 알리고 구현한다. 인수조건을 변경하면 설계도 함께 갱신한다.
5. 동작을 검증하는 테스트를 작성하고 `bash scripts/harness/verify.sh`를 실행한다. 커밋된 변경까지 포함하면 `--base <merge-base>`를 사용한다. 동일 diff의 검증 결과가 있으면 재사용한다.
6. 엔티티 변경 시 compileJava와 ERD 갱신, ENUM 변경 시 LLD 영향 범위에 ALTER TABLE, API 변경 시 controller/docs의 Swagger를 반영한다.
7. [review](../review/SKILL.md)로 자체 검수한다. 결함은 수정하고 관련 검증을 다시 실행한다. 반복 실패는 원인을 조사하고 미해결 내용을 보고하며 성공 처리하지 않는다.
8. 작업 결과와 검증 증거를 보고한다. 커밋 요청이 포함되면 [commit](../commit/SKILL.md)을, PR 요청이 포함되면 [pr](../pr/SKILL.md)을 이어서 수행한다.

## 범위

한 구현 단위는 한 목적을 가진다. LLD 밖 기능을 추가하지 않는다. 사용자에게 설계 작성을 떠넘기거나, 이미 요청한 구현의 계획 승인을 관례적으로 다시 요구하지 않는다. 독립 에이전트 검수는 사용자가 요청한 경우에 사용하며 자체 검수를 독립 검수라고 보고하지 않는다.
